# Build an Angular feature

1. Read the generated project's `AGENTS.md`, inspect the related feature and route, and reuse existing services, tokens and design patterns.
2. Put route-level UI in `src/app/features/<feature>/`. Add lazy `loadComponent` routes before the wildcard route. Keep shared concerns in `src/app/core/`.
3. Use standalone components, strict types, signals for local state, `inject()` for dependency injection, and `OnPush` change detection. Avoid introducing NgModules or Zone.js.
4. Use accessible semantic markup, visible focus, keyboard operation, responsive SCSS, and existing design tokens. Keep component styles scoped.
5. Make HTTP calls through `HttpClient`. Use relative API paths so `api-base-url.interceptor.ts` can apply the runtime `APP_CONFIG.apiUrl`; keep error handling in the shared interceptor unless the feature needs a specific recovery path.
6. Keep runtime configuration in `public/config.json` and consume it through `APP_CONFIG`. Never expose credentials or secrets in client-side code.
7. Keep SSR safe: do not access browser globals during module initialization. For browser-only flows, use platform checks or configure the route for client rendering.
8. Add or update focused Vitest tests alongside behavior changes. Before handing off, run `npm run lint`, `npm test`, `npm run format:check`, and `npm run build` when the task permits verification.
